## 使用方式

- 点击顶部扩展菜单里的 **SoulLink** 图标打开面板。
- 面板底部版本号（如 `v1.1.6`）右侧的小胶囊会联网对比 GitHub 仓库的 manifest.json 版本号：已是最新版显示「已是最新版」，有更新则显示「发现新版本 vX.Y.Z」，联网失败显示「检查失败，点击重试」；点击胶囊可随时强制重新检查（结果缓存 1 小时）。
- 面板底部 GitHub 链接左侧是主题按钮，显示当前主题名（如「🎨 手绘涂鸦」）；点击弹出主题菜单，选择后立即生效并持久化保存。目前内置「手绘涂鸦」（默认）、「聊天气泡」（浅灰底 + 白色圆角卡片 + 蓝色渐变）与「古风典雅」（宣纸底 + 墨色描边 + 朱砂印章 + 鎏金点缀）三套主题，后续版本会陆续补充。
- 右下角常驻悬浮球：单击打开面板，拖拽可移动（位置自动记忆），长按 650ms 隐藏。
- 关闭面板后悬浮球会重新出现，保证随时有入口。
- 打开面板后默认进入首页启动器，点击「API 连接」图标进入配置页：填入 OpenAI 兼容接口的 Base URL 与 API Key，点击「连接并拉取模型」即可拉取模型列表并选择模型；部分不支持 /models 的渠道可手动填写模型名称。
- 「API 连接」页模型下方可设置「限制并发」（默认开启，上限 3）：同时发送的 AI 请求数达到上限后，多出的请求会排队等待，前面的请求完成后再发送；排队时 toast 会实时显示「当前 N 个请求正在排队等待」，队列清空后自动关闭。点击开关可随时关闭限制，输入框可调整并发上限（1–10）。
- 首页第二个图标「日志系统」：打开后台日志控制台，实时观察程序运行状态，方便 DEBUG。捕获范围：`console` 输出、未捕获的 `window` 错误与 Promise 拒绝、Tavern 宿主关键事件（聊天切换 / 生成开始结束 / 设置加载等）、SoulLink 自身的关键操作（启动、菜单注册、API 连接等）、以及**全部网络请求**（`fetch` 旁路观察：方法 / URL / 请求头 / 请求体 / 响应状态 / 耗时 / 响应头 / 响应体）。
- **DEBUG API 调用**：在日志系统里筛选「网络请求」来源，点击任意一条展开即可看到完整内容——chat/completions 的请求体就是发出去的提示词（`messages`）与参数（`temperature` 等），响应体就是模型返回的内容（`choices[0].message.content` 与 usage）。密钥类字段（Authorization / api_key / password 等）自动脱敏为 `***`，可放心复制导出。
- 首页第三个图标「预设」：集中管理四个子系统的提示词（档案系统 / 档案预筛 / 角色扮演 / 角色预筛）。四个标签页分别编辑，底部显示字数与行数、状态胶囊（默认内容 / 已保存的自定义内容 / 未保存的更改）；「保存」写入 Tavern 设置持久化，「恢复默认」一键还原出厂提示词（有自定义内容时会先确认）。未保存的修改在标签页间切换不会丢失。四份默认提示词统一「回复必须且只能是 JSON 对象」的硬约束——「角色扮演」采用完整模块化架构（任务 → 输入 → 推演 → 动机参考 → 输出 → 质量红线 → 示例，输出契约是唯一最高优先级），「档案系统」与「档案预筛」采用精简模块化架构（档案系统：输入 → 档案结构 → 输出契约 → 决策规则；档案预筛：任务 → 输入 → 判断 → 输出，候选集规则收敛到输入、输出契约是唯一最高优先级），「角色扮演预筛」采用精简模块化架构（任务 → 输入 → 推演 → 判定标准 → 输出 → 质量红线，候选集规则收敛到输入、输出契约是唯一最高优先级）；预筛提示词要求输出名单全名（即使对话里用简称），「档案系统」默认提示词内置记忆质量标准（自包含 / 时间锚点 / 事件+意义 / 去重合并 / 空档案初始化），「角色扮演」提示词内置行为倾向推演（六步推演流程 / 三要素 / 两种认知状态 / 质量红线 / 双风格示例，行动倾向聚焦对玩家已做行为的即时回应）与记忆消费指令，旧默认文本（未自定义）会自动迁移升级。
- 首页「角色扮演」：输入角色名字后点击「注册当前角色」（或回车）即可把角色加入名单；列表支持一键注销（带确认框，注销会删除该角色档案数据）。名单与当前聊天绑定，切换聊天后看到各自独立的名单。页面下方提供「🎭 前置推演」开关（默认开启），控制发送前 NPC 行为推演。
- 首页「档案系统」：展示已注册角色的完整档案（姓名 / 年龄 / 性别 / 职业 / 性格 / 世界观 / 家庭背景 / 人际关系 / 记忆）。「✏️ 编辑」可手动修改字段与分节；「🔮 分析本角色」会用最近 4 条聊天消息 + 当前档案 + 世界书（按酒馆规则触发并注入），配合「预设」里的「档案系统」提示词调用 AI 增量更新档案；「🔮 分析全部角色」并发分析名单里所有角色。多个「分析本角色」可以同时点击、并发执行；分析进行中按钮会变为「⏹ 取消分析角色 / 取消分析全部角色」，点击即可中断对应 API 调用（全部中断后按钮自动复原）。
- **自动档案维护**（默认开启，档案系统工具栏「⚡ 自动维护」可随时开关）：每轮 AI 回复生成结束（`generationEnded`）后自动启动一次「档案预筛」Gate——只向模型提供已注册角色名单 + 最近 4 条消息，由模型判断本轮哪些角色的信息/记忆会变化；随后对入选角色并发复用「分析本角色」的完整档案分析流程（含世界书注入与增量更新）。同一末条只处理一次（签名去重），上一轮未跑完时新事件自动跳过，生成被中断时静默跳过。运行过程有 toast 提示：预筛完成（入选 X/Y 个角色 / 本轮无角色需要更新）、逐角色更新结果、最终汇总；API 未配置时会警告提示。「档案预筛」Gate 请求按「预筛提示词 → 名单块（`<Registered_Characters>`）→ 剧情块（`<Recent_Messages>`，最近 4 条）→ 输出契约」四段式组织。
- **发送前角色推演**（开关位于「角色扮演」页，默认开启）：点击发送按钮会先由「角色预筛」Gate 从已注册名单里选出本轮有戏份的角色，再对各角色**独立并发**调用「角色扮演」子 agent（每个角色只拿到自己的档案 + 最近 4 条消息），把推演结果按统一格式注入到**最后一条用户消息正下方**，随后才恢复发送、交给主模型生成。推演有 45 秒硬超时，Gate 失败 / 全部推演失败 / 超时都会自动放行发送；每轮生成结束后自动清空注入，不会泄漏到 swipes / 重生成 / 下一轮。开关可随时切换（没有注册角色或 API 未配置时零开销直接放行）。「角色扮演」默认提示词按「任务 → 输入 → 推演 → 动机参考 → 输出 → 质量红线 → 示例」模块化组织，内置六步推演流程（在场判定 → 情境定性 → 动机检索 → 记忆触发 → 形成假设 → 行动倾向）/ 三要素（心情、想法、对玩家已做行为的即时回应）/ 信息盲区与认知框架 / 质量红线及日常与冲突双风格示例（示例按 JSON 格式示范，可在「预设」视图查看与自定义；旧默认文本会自动迁移升级）。「角色预筛」默认提示词按「任务 → 输入 → 推演 → 判定标准 → 输出 → 质量红线」模块化组织，内置高频轻量调用最快返回语义、唯一候选集约束（只从已注册名单中挑选，名单之外的角色即使出现在对话里也不列入）、逐角色三步推演（在场判定 → 戏份判定 → 归类）、三层判定标准（必须列入：开口/被点名/动作对象；应列入：在场且受直接影响、目击冲突秘密、情绪触发、行动意图积累；不列入：只是被提及/明确不在场/纯背景）、在场推断规则（未明确去向按最近一次出场推断）、戏份排序判据（与末条消息的直接关联 → 情绪积累强度 → 互动频率，最多 6 个）、开放式场景引导（末条未点名任何人时以在场角色的情绪积累与行动意图为准）与两条偏差底线（在场判定从严：宁可漏选不可错选不在场；戏份判定从宽：拿不准倾向列入）；「上一轮角色扮演」视图可查看预筛原文（Gate 返回）审计漏选/误判。预筛请求同样按「预筛提示词 → 名单块（`<Registered_Characters>`）→ 剧情块（`<Recent_Messages>`，最近 4 条）→ 输出契约」四段式组织；推演请求按「提示词 → 档案块（`<Character_Profile>`）→ 剧情块（`<Recent_Messages>`，最近 4 条）→ 输出契约」四段式组织，档案与剧情各自 XML 包裹并带引导语。
- **删楼联动档案清理**：档案分析写入的每条条目都会记录「来源楼层」（该次分析时的末条消息）。玩家删除楼层或重生成后，程序自动清除来源为该楼层的档案条目并 toast 提示，避免档案保留已被删除的剧情信息；手动编辑新增的条目不受影响。只有楼层数实际减少才视为删楼——其他扩展原地改写消息内容（如智绘姬把生图提示词插回最新楼层）只更新溯源快照、不会误删档案。
- **正则过滤**：「API 连接」页底部可管理消息过滤正则（新建 / 编辑 / 删除 / 启停 / 导入 / 导出）。档案分析、档案预筛、角色扮演预筛、角色推演这四种调用导入的最近几条消息都会先按启用的正则剔除匹配内容（默认自带「智绘姬」过滤，剔除 `<image>...</image>` 图片占位块）；整条内容都被匹配的消息不再进入上下文。
- 首页「世界书」：展示当前聊天激活的世界书与全部条目（按书分组）。触发规则**完全由 SillyTavern 决定**（扫描深度 / 递归 / 概率 / 预算 / 粘性冷却等），本程序只做「读取激活结果 → 排除 → 按酒馆位置注入」。勾选「排除」的条目会永久从档案分析的注入中移除（按 书名+条目uid 存储，不随显示名变化失效）；「本次触发」标记当前扫描中实际被酒馆触发的条目；「清除排除」一键还原。宿主未提供条目级激活数据时会降级为「按酒馆原文整体注入」并给出提示（此时无法逐条排除）。
- 日志控制台支持：按级别筛选（全部 / 调试 / 信息 / 警告 / 错误，带实时计数）、按来源筛选（网络请求 / SoulLink / 控制台 / 宿主事件等）、关键词搜索（覆盖展开详情）、暂停 / 继续（暂停期间新日志只入内存并计数 +N，不追加、不泄漏；点「继续」一次性显示）、自动跟随最新（仅列表在底部时自动滚动，上翻不打断阅读，出现「回到最新」按钮）、清空、复制为纯文本、导出完整 JSON 文件（含暂停期间缓冲）；内存保留条数可调（默认 2000 条，环形覆盖最旧日志）。首页日志卡片会实时显示已记录条数与错误数。
- **噪音治理**：默认过滤 Tavern 内部刷屏日志——世界书扫描 `[WI]`、宏变量 dump `[Prompt Template]`、正则脚本跳过、事件总线 `Event emitted`、元数据保存、以及非模型网络调用（`ipc.localhost/*`、`/api/chats/save`），模型 API 请求与 SoulLink 自身日志永不误伤（「🔇 过滤噪音」按钮可随时开关）；连续重复出现的相同日志自动折叠为一条并显示 `×N`；所有日志（含 console 捕获）的密钥类内容一律脱敏为 `***`，可放心复制导出。
- 其他扩展如需写入日志，可调用全局 `SoulLinkLog.info / warn / error / debug`（或 `SoulLinkLog.log`）。

## 开发

- `index.js`：入口，负责菜单图标、悬浮球、面板脚手架、首页启动器（视图切换）、API 连接（OpenAI 兼容）、日志系统、预设系统（含四份默认提示词）、角色扮演、档案系统（含 AI 分析调度）、自动档案维护（Gate 预筛 + 并发分析）、世界书系统（读取酒馆激活结果 / 排除管理 / 按位置注入）、剧情前置 NPC 推演（messageSent 阻塞监听 + Gate 预筛 + 并发推演 + setExtensionPrompt 注入）与消息正则过滤（四种调用的最新消息按正则剔除，UI 在 API 连接页）。
- `prompts/`：四份默认提示词外挂文件（档案系统 / 档案预筛 / 角色扮演 / 角色预筛各一个 `.txt`）。改默认提示词直接编辑对应文件，然后双击 `build.bat`（或 `node build.js`）重新生成 `index.js`（构建产物，勿手改），重启酒馆生效；构建会自动快照旧默认，重启后已保存旧默认的用户自动迁移到新内容，无需改代码。
- `style.css`：悬浮球、面板与 API 表单样式（跟随 SillyTavern 主题变量）。
- 重启 Tavern（或刷新扩展列表）后生效。
